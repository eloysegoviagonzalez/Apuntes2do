Otras formas de paralelismo: ILP y TLP

Mas alla de del paralelismo a nivel de datos (DLP) y a nivel de procesos (PLP),existen mas formas de paralelismo.

# ILP: paralelismo a nivel de instrucción
si dividimos la instruccion en, digamos, 5 etapas con captura de instrucción, decodificado, ejecución, acceso a memoria y  escritura, estas definiendose como las unidades funcionales que se usan en varias etapas.

Esto significa que podriamos, si queremos, ejecutar varias partes de una misma instrucción a la vez.

Para esto deberiamos introducción de pipeline, que es el camino de datos segmentado en unidades funcionales  como la ALU, buses, registros, cache, y otros elementos de este. También, podemos definir un camino de datos por todo aquello que no es un procesador, por lo que tenemos paralelismo a nivel de instrucción.

Es importante, comentar que el paralelismo a nivel de instrucción necesita de la separación entre la cache L1 de instrucciones (L1-I) y L1 de datos (L1-D) para poder ejecutarse varias veces.

Aqui vemos que como tal, por ciclo, un procesador con ILP, o segmentado, posee una  mayor eficiencia que un procesador sin ILP, o sin segmentar, llendo de cinco ciclos por fin/inicio de instrucción a solo una, de hecho la versión mas sotisficada es la superescalar donde podemos ejecutar todo en dos pipelines

y la eficiencia sube, en este caso, a dos instrucciones por ciclo de reloj, aunque necesitamos una cantidad enesima de pipelines para poder aumentar la cantidad de instrucciones por ciclo de instrucción a un valor $n$.

Normalmente se determina como superescalar.
# TLP: paralelismo a nivel de hilo (thread)
A esto comunmente se les llama sistemas de multithreading, donde se busca mejorar el rendimiento global del sistema ejecutandose multiples hilos de forma simultanea o alterna dentro del mismo núcleo fisico, pero primero debemos definir lo que es un hilo.
***
## Que es un Hilo?
Un hilo que se puede definir como un proceso de computador, asi que un nucleo multihilo es aquel que puede tener varios hilos
***

Esta capacidad de multithreading trae la capacidad a los nucleos de ser capaces de ejecutar varios nucleos a la vez, de varias maneras como estan visibles

![c31452488cedadceaf0a5b87457ff08b.png](:/d947f3475e6944de93fd51ec36d03634)


siendo entre ellos los determinantes el Fine-Grained(cada ciclo), el Coarse-Grained(cada ciclo de alta latencia) y el Simultaneo. Todos ellos usan arquitectura multiescalar junto al multithreading.

Esto permite tener nucleos logicos dentro de nucleos fisicos, denominado como hyperthreading o como SMT
